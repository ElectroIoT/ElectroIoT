## 1. How the profile repository works

GitHub treats one repository as special: a **public repository whose name is
exactly your username**. Its `README.md` is rendered at the top of your profile
page.

| Item | Value |
| :--- | :--- |
| Repository name | `electroiot` (must match the username exactly, case-insensitive) |
| Visibility | **Public** — a private repository will not render |
| Rendered file | `README.md` at the repository root |
| Default branch | `main` (the workflows in this repo target `main`) |
| Profile URL | `https://github.com/electroiot` |

## 2. First-time installation

```bash
cd electroiot

git init
git branch -M main
git add .
git commit -m "feat: premium ElectroIoT profile"

# Create the repository first at https://github.com/new
#   Name: electroiot   Visibility: Public   Do NOT add a README
```

```bash
git clone https://github.com/electroiot/electroiot.git
cd electroiot
```

## 3. How to enable GitHub Actions

Both workflows need Actions turned on **and** permission to write back to the
repository.

### Step 1 — turn Actions on

1. Go to `https://github.com/electroiot/electroiot`
2. **Settings** → **Actions** → **General**
3. Under **Actions permissions**, choose
   **Allow all actions and reusable workflows**
4. Click **Save**

### Step 2 — grant write permission

Still on **Settings → Actions → General**, scroll to
**Workflow permissions**:

1. Select **Read and write permissions**
2. Tick **Allow GitHub Actions to create and approve pull requests**
3. Click **Save**

> Without this step the snake workflow cannot create the `output` branch and
> the metrics workflow cannot commit its SVG panels. Both fail with
> `403: Resource not accessible by integration`.

### Step 3 — run them once by hand

1. Open the **Actions** tab
2. Select **Snake Animation** → **Run workflow** → **Run workflow**
3. Select **GitHub Metrics** → **Run workflow** → **Run workflow**

Both should finish green. The snake takes roughly 30 seconds, metrics between
two and five minutes because it renders eight separate panels.

## 4. How to enable the snake animation

The snake workflow needs **no secret** — the built-in `GITHUB_TOKEN` is enough,
as long as workflow write permission is enabled (section 3, step 2).

### What it does

1. Reads your public contribution calendar
2. Renders a snake that eats every contribution square
3. Writes three files into `dist/`
4. Force-publishes `dist/` to a branch called `output`

### The files it produces

| File | Purpose |
| :--- | :--- |
| `github-snake.svg` | Light theme, used by the `prefers-color-scheme: light` source |
| `github-snake-dark.svg` | Dark theme with the neon-blue palette, the default |
| `github-snake.gif` | Animated GIF fallback |

### Where the README points

```html
<img src="https://raw.githubusercontent.com/electroiot/electroiot/output/github-snake-dark.svg" />
```

If you forked this profile, replace **both** occurrences of `electroiot` in that
URL with your own username.

### Changing the snake colours

Edit the `outputs:` block in `.github/workflows/snake.yml`. Colours must be
**URL-encoded** — `#` becomes `%23`:

```yaml
outputs: |
  dist/github-snake-dark.svg?palette=github-dark&color_snake=%2300C8FF&color_dots=%23111827,%230066FF,%2300C8FF,%2300FFD5,%23EAF6FF
```

| Parameter | Meaning |
| :--- | :--- |
| `palette` | Base theme, `github-dark` or `github-light` |
| `color_snake` | The snake body colour |
| `color_dots` | Five comma-separated colours: empty square, then four contribution levels |

### Schedule

```yaml
schedule:
  - cron: "15 0 * * *"    # every day at 00:15 UTC
```

Scheduled workflows on a repository with no recent activity can be disabled by
GitHub after 60 days of inactivity; a single manual run re-enables them.

## 5. How to enable GitHub Metrics

Unlike the snake, metrics **requires a Personal Access Token**, because it reads
aggregate data across your account.

### Step 1 — create the token

1. Go to <https://github.com/settings/tokens>
2. **Generate new token** → **Generate new token (classic)**
3. Note: `METRICS_TOKEN — profile metrics`
4. Expiration: **No expiration** (or set a reminder to rotate it)
5. Scopes:

| Scope | Required? | Why |
| :--- | :--- | :--- |
| `public_repo` | **Yes** | Read public repository data |
| `read:user` | Recommended | Profile details and follower counts |
| `repo` | Only if you want private repo stats counted | Full repository read |
| `read:org` | Only for organisation data | Organisation membership |

6. **Generate token** and copy it immediately — it is shown once.

### Step 2 — store it as a repository secret

1. **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret**
3. Name: `METRICS_TOKEN` (exactly — the workflow reads this name)
4. Secret: paste the token
5. **Add secret**

### Step 3 — run the workflow

**Actions** → **GitHub Metrics** → **Run workflow**.

### Panels this repository renders

| File | Plugin | Shows |
| :--- | :--- | :--- |
| `metrics/metrics.svg` | base + languages + lines | Overview, activity, community |
| `metrics/metrics.achievements.svg` | `achievements` | Unlocked achievements, compact |
| `metrics/metrics.languages.svg` | `languages` indepth | Bytes, percentage and lines per language |
| `metrics/metrics.isocalendar.svg` | `isocalendar` | Isometric full-year calendar |
| `metrics/metrics.calendar.svg` | `calendar` | Classic full-year calendar |
| `metrics/metrics.lines.svg` | `lines` | Lines added and removed |
| `metrics/metrics.habits.svg` | `habits` | Time-of-day and weekday charts |
| `metrics/metrics.stars.svg` | `stars` + `stargazers` | Most starred repositories |

### Adding another panel

Append a step to `.github/workflows/metrics.yml`:

```yaml
      - name: Followup
        uses: lowlighter/metrics@latest
        with:
          token: ${{ secrets.METRICS_TOKEN }}
          user: ${{ env.METRICS_USER }}
          filename: metrics/metrics.followup.svg
          base: ""
          config_timezone: ${{ env.METRICS_TIMEZONE }}
          plugin_followup: yes
          plugin_followup_sections: repositories
```

Then embed it in the README:

```html
<img src="metrics/metrics.followup.svg" width="100%" alt="Issue and PR follow-up" />
```

The complete plugin catalogue lives at
<https://github.com/lowlighter/metrics#-plugins>.

### Timezone

Every step reads a shared environment variable:

```yaml
env:
  METRICS_TIMEZONE: Asia/Kolkata
```

Change it to your own [IANA timezone](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones)
so the habits and calendar panels align with your actual working hours.

## 6. How to replace the profile image

The hero banner contains a **circular avatar frame** with an animated ring and a
lightning-bolt monogram. There are three ways to personalise it.

### Option A — keep the monogram, change the mark

Open `assets/hero.svg` and find the avatar group:

```xml
<!-- Avatar ring (profile image placeholder) -->
<g transform="translate(378 186)">
  ...
  <!-- lightning-bolt monogram -->
  <path d="M4 -20 L-12 2 H-1 L-5 20 L12 -3 H1 Z" fill="url(#neonGrad)" filter="url(#glowSm)"/>
</g>
```

Replace the `<path>` with your own icon path, or with initials:

```xml
<text x="0" y="14" text-anchor="middle" font-family="'Segoe UI',sans-serif"
      font-size="38" font-weight="800" fill="url(#neonGrad)">EI</text>
```

### Option B — embed a real photo inside the hero

1. Add your photo to `assets/` as `avatar.png` (square, at least 400×400)
2. Add a clip path inside the `<defs>` block of `assets/hero.svg`:

```xml
<clipPath id="avatarClip"><circle cx="378" cy="186" r="40"/></clipPath>
```

3. Add the image just before the monogram path:

```xml
<image href="avatar.png" x="338" y="146" width="80" height="80"
       clip-path="url(#avatarClip)" preserveAspectRatio="xMidYMid slice"/>
```

> Relative `href` values resolve against the SVG's own location, so keep
> `avatar.png` in the same `assets/` folder. A remote `https://` URL also works.

### Option C — show your GitHub avatar next to the hero

Add this anywhere in the README — GitHub always serves your current avatar:

```html
<img src="https://github.com/electroiot.png" width="150" alt="Profile photo" />
```

### Social preview image

`assets/preview.png` is the card shown when the repository is shared on social
platforms. To use it:

**Settings** → **General** → **Social preview** → **Upload an image** →
select `assets/preview.png`.

Recommended dimensions are 1280×640.

## 7. How to customise the colours

The whole profile runs on six colours. Changing them is a find-and-replace
across two categories of file.

### The palette

| Role | Hex | Used for |
| :--- | :--- | :--- |
| Primary | `#00C8FF` | Titles, borders, primary glow |
| Secondary | `#0066FF` | Depth, secondary strokes, gradients |
| Accent | `#00FFD5` | Highlights, pulses, "live" indicators |
| Background | `#050816` | Page and card background |
| Cards | `#111827` | Panel fills |
| Text | `#EAF6FF` | Body copy |

### Step 1 — the SVG assets

Every SVG in `assets/` and `assets/cards/` uses those hex values literally.
A recursive replace covers all of them:

```bash
# macOS / Linux
grep -rl '00C8FF' assets | xargs sed -i 's/00C8FF/FF6B00/g'
```

```powershell
# Windows PowerShell
Get-ChildItem -Path assets -Recurse -Filter *.svg |
  ForEach-Object {
    (Get-Content $_.FullName) -replace '00C8FF','FF6B00' |
      Set-Content $_.FullName
  }
```

Repeat for each colour you are changing. Work from the least common colour to
the most common so intermediate values never collide.

### Step 2 — the widget URLs

Third-party widgets take their colours from query parameters. In `README.md`
the same six hex values appear **without** the `#`:

| Widget | Parameters to update |
| :--- | :--- |
| Shields.io badges | the colour after the label, plus `labelColor` and `logoColor` |
| Typing SVG | `color`, `background` |
| Readme Stats | `bg_color`, `title_color`, `text_color`, `icon_color`, `ring_color` |
| Streak Stats | `background`, `stroke`, `ring`, `fire`, `currStreakLabel`, `currStreakNum`, `sideNums`, `sideLabels` |
| Activity Graph | `bg_color`, `color`, `line`, `point`, `area_color`, `title_color` |
| Trophies | `theme` — pick from the [theme list](https://github.com/ryo-ma/github-profile-trophy#-themes) |
| Metrics | `plugin_languages_colors` in `metrics.yml` |
| Snake | `color_snake`, `color_dots` in `snake.yml` (URL-encode `#` as `%23`) |

### Step 3 — preview before pushing

Open any SVG directly in a browser to check it, and use the
[GitHub Markdown preview API](https://docs.github.com/en/rest/markdown) or a
local editor preview for the README. Animation only plays in a real browser —
some editors render the first frame only.

## 8. How to edit the projects

### Editing an existing featured project

Each of the six featured projects is a two-column `<table>` in `README.md`
under the **Featured Projects** heading. The structure is always the same:

```html
<table>
  <tr>
    <td width="46%" valign="top">
      <img src="assets/solar.svg" width="100%" alt="Solar Bridge" />
    </td>
    <td width="54%" valign="top">

### 01 · Solar Bridge

<!-- status badges -->
<!-- description paragraph -->
<!-- Features list -->
<!-- Tech stack icons -->
<!-- Buttons -->

</td>
  </tr>
</table>
```

Two rules keep the Markdown inside the HTML working:

1. Leave a **blank line** after the opening `<td>` and before the closing `</td>`
2. Keep the `</td>` and `</tr>` at the **start of the line**, not indented

Alternate the image column between left and right on successive projects — that
zig-zag is what makes the section feel designed rather than listed.

### Adding a new project

Copy any project block and change five things:

| Element | How |
| :--- | :--- |
| Heading | `### 07 · Your Project` |
| Illustration | Point at one of the five illustrations, or a new SVG in `assets/` |
| Status badges | Change the label and colour in the shields.io URL |
| Tech icons | Edit the `i=` list in the skillicons URL |
| Buttons | Point the `href` at the real repository or docs page |

### Status badge presets

```html
<!-- Production -->
<img src="https://img.shields.io/badge/STATUS-Production-00FFD5?style=flat-square&labelColor=050816" alt="Status" />
<!-- Active development -->
<img src="https://img.shields.io/badge/STATUS-Active%20Development-00C8FF?style=flat-square&labelColor=050816" alt="Status" />
<!-- Beta -->
<img src="https://img.shields.io/badge/STATUS-Beta-0066FF?style=flat-square&labelColor=050816" alt="Status" />
<!-- Archived -->
<img src="https://img.shields.io/badge/STATUS-Archived-64748B?style=flat-square&labelColor=050816" alt="Status" />
```

### Tech-stack icons

Icons come from [skillicons.dev](https://skillicons.dev). Build the URL by
listing slugs after `i=`:

```html
<img src="https://skillicons.dev/icons?i=laravel,vue,tailwind,mysql,redis,docker&theme=dark" height="34" alt="Stack" />
```

The full slug list is at <https://skillicons.dev>. Unknown slugs are silently
skipped, so verify each one renders.

### Adding a repository pin instead of a card

If a project has a real public repository, a live pin is more informative:

```html
<a href="https://github.com/electroiot/solar-bridge">
  <img src="https://github-readme-stats.vercel.app/api/pin/?username=electroiot&repo=solar-bridge&bg_color=050816&title_color=00C8FF&text_color=EAF6FF&icon_color=00FFD5&hide_border=true&border_radius=16" alt="Solar Bridge" />
</a>
```

Only use this once the repository actually exists — a pin for a missing
repository renders an error card.

### Editing the capability cards

The eleven cards in `assets/cards/` share one template. To edit a card's copy,
open the file and change the three text blocks:

```xml
<text x="96" y="46" ... >Solar Bridge</text>                 <!-- title -->
<text x="96" y="68" ... >First description line</text>       <!-- line 1 -->
<text x="96" y="83" ... >Second description line</text>      <!-- line 2 -->
```

Keep each description line under roughly 52 characters so it does not overflow
the card. SVG text does not wrap automatically.

To add a **new** card, copy the closest existing file, rename it, and change
every `id` prefix inside it (for example `sb-` → `xx-`). Duplicate gradient or
filter IDs across two SVGs on the same page cause one card to inherit the
other's colours.

## 9. How to deploy

### Deploying the profile itself

The profile "deploys" on push — there is no build step.

```bash
git add .
git commit -m "feat: update profile"
git push origin main
```

Both workflows are triggered by that push, so the snake and metrics refresh
automatically.

### Cache behaviour

GitHub proxies every external image through **Camo** and caches aggressively.
After changing a widget URL you may keep seeing the old image for a while.

| Situation | Fix |
| :--- | :--- |
| Local SVG changed but old version shows | Hard refresh, `Ctrl` + `Shift` + `R` |
| Widget colours not updating | Add a cache-buster: `&v=2` on the URL |
| Metrics panel stale | Re-run the metrics workflow manually |
| Snake stale | Re-run the snake workflow manually |

### Deploying the same content as a website

The README is Markdown plus sanitised HTML, so it also works as a static site.

**GitHub Pages**

1. **Settings** → **Pages**
2. Source: **Deploy from a branch**
3. Branch: `main`, folder: `/ (root)`
4. Save — the site appears at `https://electroiot.github.io/electroiot/`

**Custom domain**

1. Add a `CNAME` file at the repository root containing `profile.electroiot.in`
2. Create a DNS `CNAME` record pointing that subdomain at `electroiot.github.io`
3. Back in **Settings → Pages**, enter the custom domain and tick
   **Enforce HTTPS**

> Keep the profile README and any Pages site in the same repository so the
> assets resolve from one place.

### Forking this profile for another account

Six things need renaming:

1. Repository name → your username
2. Every `electroiot` occurrence in `README.md` (widget usernames and links)
3. The two `raw.githubusercontent.com/electroiot/electroiot/output/...` URLs
4. `https://electroiot.in` → your own site
5. `hello@electroiot.in` → your own address
6. `METRICS_TIMEZONE` in `metrics.yml`

The workflows themselves need no edits — they use
`${{ github.repository_owner }}`.

## 11. Troubleshooting

<details>
<summary><b>The README does not appear on my profile</b></summary>

<br />

The repository name must match your username **exactly** and the repository must
be **public**. Rename under **Settings → General → Repository name**. Also check
that the file is `README.md` at the repository root, not inside a folder.

</details>

<details>
<summary><b>Snake workflow fails with 403</b></summary>

<br />

Workflow write permission is missing. **Settings → Actions → General →
Workflow permissions** → **Read and write permissions** → **Save**, then re-run
the workflow.

</details>

<details>
<summary><b>Snake image is a broken icon</b></summary>

<br />

Three likely causes:

1. The workflow has never completed — check the **Actions** tab
2. The `output` branch does not exist — confirm in the branch dropdown
3. The username in the raw URL does not match your account

The URL must read
`https://raw.githubusercontent.com/<user>/<user>/output/github-snake-dark.svg`.

</details>

<details>
<summary><b>Metrics workflow fails with "Bad credentials"</b></summary>

<br />

The `METRICS_TOKEN` secret is missing, misspelled or expired. Secret names are
case-sensitive. Generate a fresh classic token with `public_repo` and save it
again under **Settings → Secrets and variables → Actions**.

</details>

<details>
<summary><b>Metrics panels render but are empty</b></summary>

<br />

Some plugins need data to exist. `plugin_habits` needs recent commits and
`plugin_stars` needs starred repositories. Plugins that read private or traffic
data additionally need the `repo` scope on the token. Remove the plugins that do
not apply to your account rather than leaving empty panels in the README.

</details>

<details>
<summary><b>Stats card shows "Maximum retries exceeded"</b></summary>

<br />

The shared instance of github-readme-stats is rate-limited. It usually clears
within an hour. For a permanent fix, deploy your own instance to Vercel by
following <https://github.com/anuraghazra/github-readme-stats#deploy-on-your-own>
and swap the hostname in the README.

</details>

<details>
<summary><b>SVG animations do not play</b></summary>

<br />

GitHub allows SMIL animation inside SVG but strips `<script>`. Confirm the file
contains no script tags, then hard refresh to bypass the Camo cache. Note that
animation is also disabled for users who have set
*prefers-reduced-motion* at the operating-system level.

</details>

<details>
<summary><b>A card shows the wrong colours</b></summary>

<br />

Two SVGs on the same page are using the same gradient or filter `id`. Every
card in `assets/cards/` uses a unique prefix (`sb-`, `ha-`, `td-`, and so on).
If you duplicated a card, change every `id` and every `url(#...)` reference
inside the copy.

</details>

<details>
<summary><b>Scheduled workflows stopped running</b></summary>

<br />

GitHub disables scheduled workflows on repositories with no activity for 60
days. Open the **Actions** tab and press **Enable workflow**, or push any
commit. A manual run also re-arms the schedule.

</details>

<details>
<summary><b>Table layout breaks on mobile</b></summary>

<br />

## 12. Maintenance schedule

| Cadence | Task |
| :--- | :--- |
| **Automatic, every 6 hours** | Metrics panels refresh |
| **Automatic, daily** | Snake animation regenerates |
| **Monthly** | Review featured projects, update statuses, check every external link |
| **Quarterly** | Refresh the roadmap percentages and the *Currently Working On* section |
| **Yearly** | Rotate `METRICS_TOKEN`, review action versions, refresh the social preview |

### Keeping the actions current

The workflows pin these versions:

| Action | Pinned as | Notes |
| :--- | :--- | :--- |
| `Platane/snk` | `@v3` | Major tag, receives fixes automatically |
| `crazy-max/ghaction-github-pages` | `@v4` | Major tag |
| `lowlighter/metrics` | `@latest` | Recommended by the maintainer |
| `actions/upload-artifact` | `@v4` | Major tag |

Enable Dependabot to be told when a new major appears:

```yaml
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: monthly
```
